# JILL10 PRICING · 智能产品定价工作台

一个用于读取产品 CSV、自动识别品类、执行固定价格规则并导出正确产品包的 Streamlit 工具。

## 功能

- 自动识别 UTF-8、GB18030 等常见 CSV 编码
- 两个独立上传入口：供应商原格式和 Shopify CSV 格式
- 两个入口共用完全相同的品类识别、人工纠正、价格及折扣规则
- Shopify 导出只回写 `Variant Price` 和 `Variant Compare At Price`，其余 Shopify 字段保持原样
- 区分商品首行、SKU 变体行和纯图片行
- 检查 SKU、售价、折扣及图片链接格式
- 内置各商品品类的固定美元售价区间
- 同一商品的颜色、尺寸变体保持相同价格
- 按商品稳定选择至少三分之一设置折扣
- 每个商品的售价只取决于它自己的 Handle：同一品类新增或减少商品，不会改变其他商品已有的价格；仅当不同售价数不足 4 个时才对重复项做最小调整
- 折扣率稳定分配为 12%、15% 或 18%
- 价格采用 `.99` 或 `.90` 结尾
- 按“一级品类 → 具体品类”两层识别，并使用英文详细价格表
- 无法识别时进入询问模式；未识别商品保持原价，其余商品照常修改并允许导出
- 询问模式会列出未识别商品的名称、Handle、原始分类、原售价和 SKU 数量，再选择参考品类
- 同一原始分类只生成一个统一识别结果；多数判断不一致时整组进入人工选择，不会拆成多个错误品类
- 定价结果表支持选中单个错误商品并纠正品类；单品纠正不会影响同一原始分类中的其他商品
- 定价结果表支持一次多选多个错误商品并批量纠正品类或恢复整组规则
- 定价结果支持按 Handle、原始分类和识别品类搜索，并可按一级品类及折扣状态筛选
- 每个产品包会按“原始分类 → 识别品类”汇总展示分类组和商品数量，便于快速检查混合品类产品包
- 搜索或筛选某个品类后，可一键全选当前全部结果，再统一纠正品类并重新定价
- 左侧工作区保留最近 20 次价格或品类修改记录，支持一键撤销上一次修改
- 页面采用“定价处理中心、品类与价格规则、使用说明”三部分交互结构，并显示实时识别完成度
- 定价处理中心采用单页工作台：上传后直接按产品包查看识别结果、纠正品类，并在同一页面下载单个 CSV 或批量 ZIP
- 页面提供文件数量状态、操作成功反馈和悬浮返回顶部按钮，不需要在检查、纠正和下载步骤之间来回切换
- 步骤卡片、数据概览、文件任务和主要按钮带有轻量悬停与状态动画；系统开启“减少动态效果”时会自动停用动画
- Cardigans 使用与 Sweatshirts 相同的 `$34.99–$44.99` 价格区间
- 页面提供价格范围管理入口，可修改每个品类的最低价和最高价，并可导入、下载或恢复默认价格表
- 可在已有一级品类下新增二级品类，设置最低价、最高价和识别关键词；新增品类立即参与识别、人工选择和定价
- 自定义二级品类支持删除、撤销、JSON 下载和再次导入
- Bras（包括 bra、bralette、sports bra）归入 Underwear, Sleepwear and Swimwear，不归入 Accessories
- 女士袜子套装、袜子组合和多双装袜子按 Socks 定价，不会因为 set/套装被识别成 Women's Clothing → Sets
- 新增 Watch Bands（手表表带）品类，价格范围为 `$8.99–$18.99`；普通手表仍使用 Watches 的独立价格范围
- 内置轻量本地相似度引擎：高置信且明显领先时自动采用，否则展示前三个候选、价格区间和相似度
- 相似度计算完全在应用内完成，不使用 OpenAI API，不消耗 API 额度
- 上传批次和已确认映射会临时保存在应用内存中；普通页面刷新或重新处理不会丢失，应用重启/重新部署后需重新上传
- 多人访问时自动创建随机独立工作区；每个人的上传文件、映射与结果相互隔离
- 独立工作区闲置 6 小时后自动清理；分享时只发送 `.streamlit.app` 主网址，不发送带 `?workspace=` 的个人工作区网址
- 每个已识别产品包都提供“人工纠正品类”下拉菜单，可覆盖错误识别、重新定价，也可恢复程序自动识别
- 人工确认的品类优先级最高，保存后不会再被自动冲突检查推翻
- 女装 Plus Size 在对应区间基础上采用下限 +$2、上限 +$5；男装 Plus Size 整体 +$3。标题或 tags 中出现 Plus Size 即生效，不要求原始分类也写明；在“价格范围管理”中修改基础品类区间后，Plus Size 会在新区间上继续叠加
- 价格表外商品会映射到相似基准品类，并要求人工确认
- 非零原价必须高于售价，且售价和原价都不能超出品类区间
- 同品类至少生成 4 个不同售价；不足 4 个商品时按实际商品数生成
- 导出时只替换 `price` 和 `compare_at_price`，保留其他字段原文、顺序、引号、编码和换行
- 保留原始字段顺序、图片行和商品层级
- 严格保留原文件编码及 BOM 状态；普通 UTF-8 不会被擅自加入隐藏文件头
- 导出后自动复核：重新读取即将下载的文件，确认编码、BOM、分隔符、换行符和行数不变，除价格列外所有单元格与原文件逐格一致，价格与计划值一致，同一商品各变体价格一致；任何一项不通过都会阻止下载
- Shopify 文件中，本工具新产生的“无折扣”原价写为空单元格而不是 `0`（供应商格式仍用 `0`）；如需恢复，将 `exporter.py` 中的 `SHOPIFY_EMPTY_COMPARE` 改为 `False`
- 所有价格都为空的商品不会被静默跳过，会在页面上提示
- 标题复核：即使原始分类已识别，也会读商品标题。标题里含“收纳 / Storage / Organizer / 架 / 盒”等容器词，且原始分类是服装、鞋、配饰、包袋时（例如放在 Socks 分类里的 Sock Storage Box），该商品会改按“厨房与收纳”定价，并标记为“语义匹配·标题纠正”，需要你在 ③ 中确认；人工指定过的分类不会被覆盖
- 品类识别对常见易混淆写法做了排除，例如 Tie Front Dress、Boot Cut Jeans、Short Sleeve Dress、Shelf Bra Tank、Shoe Storage 不再被误判为领带、靴子、短裤、家具或鞋
- 定价结果按“文件内容 + 规则配置”缓存，只改页面状态（切换步骤、搜索、筛选）时不会重复计算

## 本地运行

```bash
python -m pip install -r requirements.txt
streamlit run app.py
```

## 运行测试

```bash
python -m unittest discover -s tests
```

## Streamlit Community Cloud

1. 将本项目文件上传到 GitHub 仓库根目录。
2. 打开 https://share.streamlit.io/ 并连接 GitHub。
3. 点击 `Create app`。
4. 选择仓库和 `main` 分支。
5. Main file path 填写 `app.py`。
6. 点击 `Deploy`。

## 数据安全

仓库只保存程序代码。不要把公司的产品 CSV、客户资料、密码或 API Key 提交到 GitHub。
